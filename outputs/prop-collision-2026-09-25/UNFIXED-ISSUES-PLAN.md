### 4. Level 3：挂点函数坏了 → 8 个道具漂在格中心、4 个漂在房间正中

**现状**：`layout.js:188-199` 的 `getLevelThreeTargetMount` 收到格中心时 `dx = dz = 0`，
`Math.sign(0) * 1.68 = 0` → **恒等返回格中心、rotation 0**。13 个实例全部中招：

- 5 台配电柜（格 (5,5)(8,7)(14,14)(11,17)(30,19)）—— 已经带碰撞体，等于在房间正中放 1.05m 宽的实心障碍；
- 便签 (5,5)(9,8)(20,5)(23,9)(14,17)、壁画 (19,8)、紫色净化痕迹 (8,9)(32,18)。

参考实现：`src/scene/level-two/layout.js:405-438` 的 `getLevelTwoTargetMount`（按 北→南→西→东 找第一面实心邻格，
位置 = 格边 − `WALL_THICKNESS*0.7`，rotation N=0 / S=π / W=π/2 / E=−π/2）。

**方案①（推荐）**：重写 `layout.js:188-199`：

1. 四邻扫描（顺序同 level-two）取第一面实心格方向；
2. 四邻全开时 BFS 外扩最多 3 格找最近实心格（本例 4 个实例都在 2 格内）；
3. `offset = CELL_SIZE/2 - WALL_THICKNESS*0.7 = 1.846`（比现有 1.68 多 0.166m，才能贴到墙）；
4. 返回结构 `{x, z, rotation}` 保持不变。

影响：8 个贴墙实例各移动 1.846m 并旋转 0/±90°/180°，4 个无邻墙实例移动约 2 格 + 1.846m 贴到墙。
配电柜碰撞体（`props.js:52-61` 由 `mesh.position` 与 `mount.rotation` 计算 AABB）**自动跟随**，
贴墙后占地由「1.05×0.12 的房间中岛」变成贴墙薄板，走廊净宽仍约 2.9m。
bulkhead 单格（如 (8,8)）成为理想靠墙点（panel(8,7)→南、(14,14)→西、便签(9,8)→西、紫斑(8,9)→北）。

**方案②（不推荐）**：函数不动、13 个调用点各传一个偏离格心的参考点 —— 4 个无邻墙的格给不出正确方向，且仍有 0.166m 浮空。

**验证**：Node 断言每个实例的 mount 相对格中心偏移 1.846 且方向对应 `isLevelThreeOpenCell=false` 的一侧；
贴墙后 `isWalkable` 采样确认走廊可通行。

### 7. 关闭状态/打开后的门扇可以穿过（`src/scene/common/exit-network.js`，10 个关卡共用）

**现状**

- 门扇几何：单开 `2.28 × 2.35 × 0.12`（局部 x±1.14、z±0.06）；双开两片 `1.12` 宽；门框外廓 2.74×0.22、高 2.56。
- 关门态世界 AABB（Hub 侧 +1、z=126 实测）：`x 16.940..17.060 / z 124.860..127.140`；
  但 Hub 的 `|x| ≤ 16.19` 夹取已把它挡住（**冗余**）。
- **单开门打开后**门扇绕 −104.4° 转进走廊：`x 14.777..17.015 / z z₀−1.765..z₀−1.082`（凸出 2.223m），
  这一段落在可达区，是真正会被穿过的部分。`singleDoor:true` 只有 Hub（15 扇）与 Level 11（2 扇）。
- Level 5 的出口门是**平移双开**；Level 5 的三扇酒店房门（±71°）已自带 `collider.active = !opened`（`props.js:423`）。
- 触发判定 `exit-network.js:588`：`opened && openProgress > 0.72 && XZ 距离 ≤ enterRadius(默认 1.25)`。

**方案 1（推荐）：给 `createExitNetwork` 增加可选 `colliders` 参数，门扇碰撞体带 `active` 开关**

```js
createExitNetwork(scene, camera, routes, initialState, { colliders })   // 新签名
// 建路由时（跳过 threshold / stairModel / 已有手写框的 L37）：
route.doorCollider  = { /* 关门态 AABB（按 route.rotation 旋转） */, active: true };
route.swingCollider = singlePanel ? { /* 开门态 AABB（实测 2.238 × 0.683） */, active: false } : null;
colliders.push(route.doorCollider, ...(route.swingCollider ? [route.swingCollider] : []));
// updateModel() 内（551-552 之后）：
const open = route.openProgress > 0.5;
if (route.doorCollider) route.doorCollider.active = !open;
if (route.swingCollider) route.swingCollider.active = open;
```

- 闭包共享同一个 `colliders` 数组即可生效（各关 `isWalkable`/`getFloorHeight`/`resolvePosition` 都持有同一引用，
  `colliderBlocksAtFeetHeight` 已支持 `active === false`）。
- 需要传数组的调用点（10 个）：`hub/index.js:277`、`level-one:476`、`level-two:732`、`level-three:299`、
  `level-four:172`、`level-five:300`、`level-six:297`、`level-seven:495`、`level-eight:158`、`level-eleven:96`。
- **注意**：`level-four`（172 建网 vs 180 建拾取物）与 `level-eight`（158 vs 161）把出口网建在拾取物之前，
  若共用同一数组会改变拾取物落点（影响存档位置）→ 建议传独立的 `exitColliders` 数组，在 `isWalkable` 里合并；
  或把 `createExitNetwork` 调用移到拾取物之后。
- 必须跳过 `stairModel`（Level 6 的 COLD POOL 已是 `opened = true` 的楼梯间，无门扇，且已有手写碰撞体）；
  Level 37 已有手写门框碰撞体（`index.js:143-153`），可删掉改走通用机制，或保留并跳过。

**风险 / 前置**

- 触发半径够不到的风险：门平面外 0.47m（0.11 框厚 + 0.36 半径）< 1.25，余量 0.78m；
  Level 1 电梯 `entryPosition` 在门后 1.05m、Level 11 公寓门在门后 1.82m，都不受影响。
- **Hub 必须先补 `resolvePosition`**（见第 8 项），否则门关上时玩家可能被夹在门扇里只能单轴滑动。
- 方案 2（按 `openProgress` 每帧重算 AABB）也可行，成本约 2k 浮点运算/秒，可忽略，但实现略复杂。

## P2（观感/细节，可选）

### 10. Level 2：阀门交互点与轮盘埋在墙里

**现状**：交互点在实心格中心 `levelTwoCellCenter(30,14) = (22,2)`（`index.js:716-725`），
该格 N/S/E 全是墙、走廊在西侧；最近可站立 (19.64, 2) → 2.36m（半径 3.0，能触发但指向空白墙面）。
轮盘（`props.js:670-680`）无条件放在格子的 `+z` 面（(22,1.44,4.08)）→ **埋进 +z 的实心墙里**，朝向还垂直于走廊。

**方案**：① `index.js:719` 交互点 `(22,2)` → **`(20,2)`**（距最近可站立点 0.36m）；
② `props.js:670-680` 该格的轮盘改为 `x = 19.92`、`rotation.y = Math.PI/2`（通用写法：按四邻字符判定可走方向再贴面，
其余 5 格算出来仍在 +z 面、不变）。轮盘凸出墙面仅 0.054~0.12m，不与玩家胶囊冲突。
不建议放宽可行走格（阀门格不生成地板/天花板，放开会看到 4×4×3.72 的黑洞）。

### 11. Level 9：树冠糊脸（树干只挡 ±0.3m）

**现状**：树冠最低点 `1.2314 × size` = **0.96~1.43m**（注释写 1.15 是低估的），
最低层水平半径 0.385~1.809m、枝尖可达 2.26m；间距最小 8.29m，52 棵树全在可走格。
实测贴到树旁时有 54%~88% 的方位在 1.75m 以下有 ≥0.7m 半径的叶片。

**方案 C（推荐）**：抬高树冠几何 —— tier0 `base 1.48 → 2.5`（整表 +1.02：2.5 / 3.22 / 3.95 / 4.72），
树干 `1.85 → 2.6`（否则接不上），树高由 4.0~6.0m 变 4.8~7.2m。不加任何碰撞体，玩家可从树下走过。

**方案 B（保美术）**：给每棵树加树冠碰撞体 `±1.05 × size`（0.82~1.22m）→ 但 col1 树线西侧只剩 **0.06m**，
等于把地图边线变成硬墙；碰撞体总数 73 → 125（无性能问题）。
**方案 A**：保持现状，只把注释改成真实数字（0.96m / 2.26m）。

### 12. Level 12：四个悬空抽屉的 `topY` 高于跳跃顶点

**现状**：idx 10 / 40 / 97 / 126（都是 drawer），`min.y` 0.60~0.82、`max.y` 1.31~1.47；
**每个都被同 index 的桌面碰撞体完全遮蔽**（桌面 topY 1.31~1.50、XZ 完全包含），落不上去（面积不够 0.72m）。
从地面看等价于全高障碍，与可见机体（悬空金属柜）一致，**不是隐形墙**。
**方案**：保持现状（推荐），只补注释。若要做系统性重做，正确判据是「机体完全高于头顶」`min.y > 1.75`
（而非现在的 0.9），但那会让当前 50 个装饰实例全部变成障碍，改动面太大，建议单独一轮评估。

### 15. Level 12：核心房侧墙 4m 敞口 —— **不建议封**

原审计把它记成「可绕过锁门进房」，实测结论相反：**玩家出生点 (2,50) 就在房间内部**
（`layout.js:5`），而门在初始状态是锁的（`matrix-progression.js:16-19` 要求先完成椅子观察 + copycat 门，
copycat 门在房间外）→ 侧墙缺口是**唯一的出门路径**。实测把侧墙闭合后会**出生即软锁**
