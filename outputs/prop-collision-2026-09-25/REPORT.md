# 道具实体碰撞修复（Level 0 椅子 + 全关卡同类问题）

日期：2026-09-25
触发问题：**Level 0 马尼拉文档室的椅子没有实体碰撞，玩家可以直接穿过去。**

## 根因

各关卡把"可碰撞道具"登记成一个 AABB 列表（`{ minX, maxX, minZ, maxZ, topY?, sideClearance?, active? }`），
由 `FirstPersonControls` 调用关卡导出的 `isWalkable` / `getFloorHeight` / `resolvePosition` 消费。
Level 0 的椅子（`src/scene/level-zero/manila-room.js` 里的座面 + 靠背 + 4 条腿）只建了模型，
**从未登记任何 AABB**，所以玩家能整段穿过去。同一类问题在其他关卡大量存在，另外还暴露出两个系统性问题：

1. 13 个关卡的 `isWalkable` 用 `circleIntersectsAabb`（只看 X/Z、忽略 `feetY`），
   于是 `topY` 是死数据、**任何道具碰撞体都是"无限高的隐形墙"**，`getFloorHeight` / `resolvePosition` 也没有导出；
2. 少数道具虽然有碰撞体，但数值是手写的、没按模型尺寸/旋转算（偏大或偏小）。

## 修复内容

### 1. Level 0（用户报告的问题）

`src/scene/level-zero/manila-room.js`

- 新增纯函数 `getManilaRoomFurniture(center)`：给出桌子/椅子布局与碰撞体，Node 侧可复算。
- 椅子拆成**两层碰撞体**，与几何一一对应：
  - 座面 `topY = 0.625`（座面顶）——跳起后脚部越过 0.445m 就松开侧面；
  - 靠背 `topY = 1.295`（靠背顶，高于 1.15m 跳跃顶点）——仍然挡住，所以整张椅子依然是不可跳过的实体。
- 椅子模型归入 `level-zero-manila-chair` 组（同时恢复它作为"chair"参与阴影/描边的语义）。
- 桌子碰撞体沿用原值 `topY = 1.11`。

### 3. 顺带修掉的系统性问题

- `src/scene/common/grid-world.js`：新增 `createGridCollision()` → `{ isWalkable, getFloorHeight, resolvePosition }`，
  `isWalkable` 按 `colliderBlocksAtFeetHeight(collider, feetY)` 过滤，带 `topY` 的道具从此是"可跨越/可站上去的平台"而不是隐形全高墙；
  5 个使用它的关卡（8/9/10/11/37）改用它。`createGridWalkability` 保留为薄封装。
- 有道具碰撞的 **15 个关卡现在统一走 `src/scene/common/platform-collision.js`** 的三个 helper（照 Level 1 的既有写法），
  即 `isWalkable` 读 `feetY`、发布 `getFloorHeight`（站上道具顶面）与 `resolvePosition`（每帧把嵌进去的玩家推出来）。
  这同时消除了"跳起后撞隐形墙"和"落在矮道具里被卡死"两类衍生问题。

## 验证

1. **`scripts/check-prop-collision.mjs`（新增，已并入 `npm run check`）**
   - Level 0 椅子行为断言：地面被挡 / 0.46m 松开座面 / 1.0m 仍被靠背挡 / 椅子不可站（半径不够） / 嵌进去能被推出 / 椅子不与桌面碰撞体粘连 / 椅子后方通道仍可走；
   - 15 个关卡的接线回归断言（必须 height-aware 且导出 `getFloorHeight` / `resolvePosition`）。
2. **`tests/prop-collision-probe.html`（新增，浏览器验收页）：459 项检查全部通过**
   - 约 240 个探针点（每关新增/改动的碰撞体中心 + 旁边应当仍可通行的对照点）；
   - **模型占地扫描**：对渲染出来的椅子、房间桌、工作台工具的实际 `Box3` 各取 9 个采样点，全部必须被挡（避免"只堵住一个点"）；
   - **用真实 `FirstPersonControls` 模拟玩家直冲椅子**：从 (80.5, 60.78) 朝 +X 走 2.5 秒，停在 x≈81.9（座位前沿），走不过去；同一条路在椅子北侧 1.4m 处仍能自由走 7.6m（对照，证明不是"整片区域都被挡住"）；
   - 每关 **BFS 可达性**：出生点仍能走到关卡目标 / 关键门（Level 13 因三个公寓模块靠楼梯传送连接，改测同一模块内的钥匙门与公寓门）；
   - **解卡检查**：每个"被挡"探针点都调用 `resolvePosition(x, z, 0.36, feetY, 1)`，必须真的把玩家推出去。
3. `npm run check`、`npm run build` 通过。
