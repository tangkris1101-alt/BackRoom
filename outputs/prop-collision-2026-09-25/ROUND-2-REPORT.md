## 二、验证

1. **`tests/prop-collision-probe.html`（浏览器、真实关卡）：497 项全部通过**，覆盖 16 个场景（Hub + Level 0-13 + Level 37）：
   - 约 300 条探针（含本轮新增的：L3 五台贴墙配电柜、L4 三台迁移机器、L1 木箱、L2 阀门、L6/L8 门、L12 十级台阶 + 跳跃顶点 + 触发点、L13 床/门洞/管道/电梯门板/楼梯栏杆、Hub 地台与门）；
   - 模型驱动的 3 项：L0 椅子整个占地不可穿、L0 房间桌、L1 工作台工具、**L9 52 棵树的树冠最低点 ≥ 1.75m**（读实例矩阵算世界 AABB）；
   - Hub 新增：出生点 `getFloorHeight = 0.105`、中央地板 = 0；
   - L0 真实 `FirstPersonControls` 直冲椅子被挡在座位前（终点 x≈81.9），旁边同一段路仍能自由行走；
   - 每关 BFS 可达性（含 L12 改为"楼梯脚触发点 + 复制门交互点"、L13 三个模块内目标）；
   - 每个"被道具挡住"的探针点都能被 `resolvePosition` 推出（墙体/网格挡住的点不计，因为引擎本来就不允许进入）。
2. **`npm run check` 通过**，其中 `scripts/check-prop-collision.mjs` 新增断言：
   - L3 挂点：11 个实例位的挂点必须距所在格中心 1.846、且朝墙方向是实心格；地板不得再被 `(0,0,0)` 覆盖、必须与天花板同心；
   - Hub：必须按 `feetY` 过滤、发布 `getFloorHeight`/`resolvePosition`、地台必须铺到墙面；
   - 门：`exit-network.js` 必须有 `doorCollider`/`swingCollider`，10 个有门扇的关卡必须把碰撞体交给出口网；
   - L4 三台机器所在格必须可走且道具表里仍在这些格；L1 木箱必须在 (28,18)。
3. **`npm run build`（web + standalone + 打包校验）通过。**

## 三、明确不做（附实测依据）

| 项 | 原因 |
| --- | --- |
| L12 核心房侧墙 4m 缺口封堵 | 出生点 (2,50) 就在房间内部、门初始是锁的（需先完成椅子观察 + 房间外的 copycat 门）⇒ 缺口是唯一出路。实测封堵后出生即软锁（可达集缩到房内 678 个节点，复制门/楼梯均不可达）。已改为在代码里注释说明；若要"门开后才封闭"，需要动态激活补块 |
| L12 四个悬空抽屉的碰撞 | 顶面 1.31~1.47m：从地面看等价全高障碍（与可见机体一致），且顶面比 0.72m 机体窄、无法站立；改成跳过它们只会让玩家穿过悬空柜体。已在注释里记录判据（真正该重做的判据是"机体完全高于头顶 `min.y > 1.75`"，会牵动 200+ 个实例，另议） |
| L13 转移楼梯台阶碰撞 | 加台阶碰撞体后触发圆（半径 1.25）内最近只能到 1.56m ⇒ 会封死唯一跨楼层路线。只加了两侧栏杆 |
